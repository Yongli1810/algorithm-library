# 停滞触发的受控重热模拟退火

第一周算法项目。研究单车配送访问顺序：在经典模拟退火和 2-opt 邻域上，加入低温停滞检测、限次重热，以及按剩余预算重新计算降温率的机制。

**代码、四页讲解文档、交互演示和配对实验均已完成。18 项测试通过；独立验证包含 18 张地图、20 个求解种子和 3 种策略，共 1080 次求解。**

**实验没有证明当前改动整体优于基准。** 停滞触发方案的配对平均收益为 **−0.0625%**，即路线平均略长；地图层面 bootstrap 95% 区间为 **[−0.2337%, +0.0658%]**。这是一份可复现的机制改进与验证项目，保留了开发失败和独立验证的全部结果。

## 问题与核心原理

给定 n 个二维坐标，寻找节点排列 π，使闭合路线总长尽可能小：

```text
L(π) = d(π₀,π₁) + d(π₁,π₂) + ... + d(πₙ₋₁,π₀)
d(a,b) = hypot(xₐ − xᵦ, yₐ − yᵦ)
```

本项目是对称欧氏 TSP。坐标单位没有指定为现实中的公里，不包含真实路网、车辆容量、时间窗、多车分配或交通变化。

### 2-opt 候选

固定仓库在首位，抽取索引 `1 <= i < j < n`，反转 `route[i:j+1]`。设反转前连接边为 `(a,b)` 和 `(c,d)`，新连接边为 `(a,c)` 和 `(b,d)`，则：

```text
Δ = d(a,c) + d(b,d) − d(a,b) − d(c,d)
```

区间内部边的方向反转，在对称距离下长度不变，所以只需四条边计算增量。整条闭合路线的完全反向不会改变路程，采样时排除此无效操作。

### 接受与保存

```text
Δ <= 0：接受
Δ > 0：以 exp(−Δ / T) 的概率接受
```

当前路线允许暂时变差，历史最好路线单独保存。每次刷新最好记录前重新计算完整路程，另外定期校正增量累计的浮点误差。最终返回历史最好路线。

### 温度校准与重热

初始路线由最近邻法产生。在这条路线随机抽取 C 个候选，用正增量的均值估计：

```text
T₀ = mean(positive Δ) / (−ln p₀)
Tmin = q × T₀
α = q^(1/B)
```

没有正增量时使用平均路线边长作为尺度，温度最少为 1e-12。校准使用独立随机流，C 次校准计入额外预算，三组完全一致。

停滞触发策略需要同时满足：连续 K 次候选评估没有改善历史最好路程，距离上一次重热也至少 K 步，温度不超过低温门槛，重热次数未达上限，且没有进入禁止重热的最后一段预算。

```text
T′ = min(T₀, max(γ × T, f × T₀))
α′ = (Tmin / T′)^(1/(B−t))
```

这里 t 为当前候选评估次数。重热后重新计算 α，使剩余 B−t 步仍能降到与基准相同的 Tmin。触发后重置停滞计数，历史最好路线保持不变。每次普通降温均以 Tmin 为下限。

### 三种策略

| 模式 | 触发规则 | 用途 |
|---|---|---|
| baseline | 不重热 | 关闭重热组件的消融基准 |
| periodic | 到固定间隔时检查公共温度与预算条件 | 检验是否仅仅“重热”就有效 |
| stagnation | 根据历史最好值停滞触发，仍检查公共条件 | 拟研究的自适应触发规则 |

两种重热策略共用幅度、低温门槛、次数上限、截止比例和后续降温公式。实际触发次数可能不同，实验单独保存此项。

## 实验经过与结论

| 阶段 | 运行数 | 数据用途 | 保留位置 |
|---|---:|---|---|
| 初版开发 | 1080 | 初始门槛 0.1、重热下限 0.02；固定降温率 | outputs/development_v1 |
| 降温机制修正 | 270 | 同一批开发地图，每图 5 个种子；统一终温 | outputs/development_v2 |
| 开发参数比较 | 450 | 同一批开发地图，5 个候选设置各 90 次 | outputs/development_sweep |
| 独立验证 | 1080 | 18 张新地图、20 个新求解种子；配置冻结 | outputs/validation |

初版开发中，停滞触发方案相对基准的平均收益为 −1.5339%。加入共同终温的修正后，原先较高的触发门槛仍表现不佳。因此在开发地图上比较五组较低温度门槛等设置，选中 `gate_0005`；它在开发子集的平均收益仅为 +0.0591%，不能预先证明改进有效。

独立验证使用 `data_seed=20271123`，求解种子为 100–119；开发阶段的数据种子为 20261022，求解种子为 0–19 的子集。正式验证完成后没有继续按其结果调参。

| 策略 | 相对基准的配对平均收益 | 胜 / 平 / 负 |
|---|---:|---:|
| 不重热 | 0.0000% | 0 / 360 / 0 |
| 固定间隔重热 | −0.0126% | 16 / 320 / 24 |
| 停滞触发重热 | −0.0625% | 65 / 246 / 49 |

收益定义为 `100 × (基准路程 − 方案路程) / 基准路程`，正值更好。停滞触发在 20 点场景和部分 50 点场景有微小平均收益，在 100 点场景平均变差。更高的获胜次数并不必然带来更好的平均收益，因为每次胜负幅度不同。

不把不同地图的绝对路长波动当成算法随机性：先在每张地图内计算种子间标准差，再对地图取平均。区间也按地图均值重采样，而不是把同一地图的 20 次运行当成 20 张独立地图。本实验图数较少，区间只描述当前合成场景，不作普遍优越性结论。

**可报告的结论是：这套低温受控重热规则可实现、可复现，但目前没有显示整体收益。** 对其机制、适用条件和失败原因的分析，应当与代码和图表一同讲解。

## 正确性与复杂度

18 项测试覆盖四点手算、所有片段的增量计算、Held–Karp 与七点全排列对照、最好值单调性、路线完整性、随机种子复现、共同初态、关闭重热后的等价性、共同终温、零距离、重热边界和无效输入。

8 点微型示例的精确最优路长为 **190.951049**；三组在指定微型配置下均找到这个值。大规模实例没有精确最优值，实验中的改善率是相对基准的收益，不是相对全局最优的误差。

距离矩阵与最近邻初始化的时间、空间主要为 O(n²)。一次 2-opt 增量计算为 O(1)，但实际反转、完整路长复核和保存路线最多为 O(n)，因此 B 次搜索的最坏时间为 O(Bn)，总时间为 O(n² + C + Bn)。关闭轨迹时空间为 O(n² + C + R)；每 s 步保存路线时，轨迹额外为 O((B/s + R + 1)n)，R 为实际重热次数。小规模精确求解器单独为 O(n²2ⁿ) 时间，仅允许 n≤12。
